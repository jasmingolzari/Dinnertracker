# Teamwork

During Release 1, we planned and coordinated the project by dividing the work into issues and assigning tasks to group members. Group meetings have been an important part of our teamwork, where we discuss the current issues, distribute tasks among members, give status updates and discuss how the project is progressing. Members worked on separate branches and communicated through GitHub, meetings and Microsoft Teams. Working in parallel allowed several members to contribute at the same time, but we experienced challenges when tasks overlapped or depended on the same parts of the project. This sometimes required additional coordination and understanding of other members’ changes.

Microsoft Teams has also been important for communication within the group. We use it to discuss technical and organizational questions, coordinate meetings, share progress and ask for help. GitHub Issues, branches, pull requests and reviews have helped us keep track of the work. We learned that issues need to be specific enough to make it clear what needs to be done and when a task is finished. The issue and pull request templates have helped make this more consistent.

We also experienced problems with the Eclipse Che setup during Release 1. This taught us the importance of communicating problems with the group and documenting them instead of trying to solve everything individually.

Throughout the project, we have gradually learned more about Git, GitHub, Maven, JavaFX, testing, software architecture and teamwork. We have also become more comfortable asking questions and sharing knowledge when someone is struggling with an unfamiliar concept.

For Release 2, we want to use more specific issues and shorter milestones to improve coordination and give the group a clearer overview of the work. We will continue the good practices from Release 1 while addressing the feedback we received. Regular TA meetings will also continue to help us identify and resolve problems.
