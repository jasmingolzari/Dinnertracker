# Challenges 

During the projec we faced several challenges, which we solved by finding suitable solutions together. This file reflects on the two that had the greatest impact on our work. 

## Challenge 1: Blocking dependencies 

### The challenge 
Early in the project, many of our issues depended on each other.Group members therefore had to wait for others to finish before they could continue with their own issues. For example, development of the GUI could not proceed until `RecipeFileHandler`was completed. This was before we started using issue relationships, so the dependencies were not visible to the group. In Release 1, this caused many of essential issues being closed near the milestone deadline, which was something we aimed to avoid. 

### Measures 
After recognizing the problem, we introduced several measures to prevent it in later releases. We began marking blocking relationships between issues in GitHub, and we identified dependencies both when issues were created. Large tasks were split into smaller, independent parts, so that fewer task relied on one another. In addition, we held regular meetings where blockages could be uncovered early if someone was stuck. 

### Lessons learned 
A key lesson was that extra planning in advance saves considerable time and restructuring later. Making dependencies visible turns a hidden risk into something the group can plan around. Breaking large issues into smaller, independent parts also gave smoother progress, and it made it easier for antoher member to take over a task if someone got stuck.
